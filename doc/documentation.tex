\begin{abstract}
\noindent
\textbf{eMerger} is a command line tool for Linux, macOS and Windows that
refreshes, upgrades and cleans a system with one command, \texttt{up}. It
detects the package managers installed on the host, runs them in order and
prints one summary at the end. Bash on Unix, PowerShell on Windows.

\medskip\noindent
This manual covers every platform: every flag, configuration variable,
environment variable, file, exit code and JSON field, and the plugin API.
\end{abstract}

\section{Overview}\label{sec:why}
%-------------------------------------------------------

\subsection{Background}
Your software comes from lots of places:

\begin{itemize}
  \item the operating system (\texttt{apt}, \texttt{dnf},
        \texttt{pacman}, \texttt{zypper}, \texttt{softwareupdate},
        \texttt{winget} and others);
  \item cross-distribution app stores (\texttt{flatpak}, \texttt{snap},
        \texttt{brew -{}-cask}, \texttt{choco}, \texttt{scoop});
  \item user-level stores (\texttt{brew}, \texttt{mas});
  \item language ecosystems (\texttt{npm}, \texttt{pip},
        \texttt{cargo}, \texttt{gem}, \texttt{pnpm} and others);
  \item vendor firmware (\texttt{fwupdmgr} on Linux, \texttt{softwareupdate}
        on macOS, Dell/Lenovo utilities on Windows).
\end{itemize}

Each has its own commands, its own cache and its own idea of what a
security update or a clean-up is. eMerger puts them behind one command.

\subsection{What \texttt{up} does}
On any supported platform, \texttt{up}:

\begin{enumerate}
  \item detects the package managers installed on the host;
  \item asks for \texttt{sudo} (or a UAC elevation on Windows) only if a
        detected manager needs it;
  \item optionally takes a filesystem snapshot, and records the package
        list so the run can be audited afterwards;
  \item runs refresh, upgrade and clean for each manager, serially or in
        parallel where safe;
  \item optionally cleans user caches and the trash;
  \item prints a summary with the result per manager, disk freed, run
        duration and whether a reboot is needed;
  \item on request, exports the same summary as JSON or a Prometheus
        textfile.
\end{enumerate}

\section{Requirements}\label{sec:requirements}
%-------------------------------------------------------

eMerger does not install any of these; it uses whatever is there.

\subsection{Linux}
\textbf{Required:} \texttt{bash} 4.4+, \texttt{coreutils}, \texttt{git},
\texttt{sudo}.

\textbf{Optional:}
\begin{itemize}
  \item \texttt{notify-send} for desktop notifications.
  \item \texttt{curl} for the weather line (\texttt{-w}) and the
        \texttt{-{}-doctor} connectivity check.
  \item \texttt{flock} for the global lock (part of \texttt{util-linux},
        installed by default on most distributions). Without it the lock
        is the directory \verb|emerger.lock.d|.
  \item \texttt{timeout} (coreutils) for \verb|MANAGER_TIMEOUT|.
  \item \texttt{pkill} (procps) to stop the \texttt{-{}-parallel} managers
        when a run is interrupted; without it their commands finish first.
  \item \texttt{reflector} (Arch) or \texttt{netselect-apt} (Debian)
        for \texttt{-{}-refresh-mirrors}.
  \item \texttt{snapper}, \texttt{timeshift} or \texttt{btrfs-progs} for
        \texttt{-{}-snapshot} and \texttt{-{}-rollback}.
  \item \texttt{fwupdmgr} for \texttt{-{}-firmware}.
\end{itemize}

\subsection{macOS}
\textbf{Required:} \texttt{bash} 4.4 or later, and Xcode Command Line
Tools for \texttt{git}. The system \texttt{/bin/bash} is 3.2 and is too
old (eMerger uses \texttt{mapfile}, \verb|${var,,}|, \verb|{fd}|
redirections and empty-array expansion under \texttt{set -u}); install a current one with \texttt{brew install bash} and
make sure it comes first in \texttt{PATH}, since the \texttt{up} alias
runs \texttt{bash} from \texttt{PATH}.

\textbf{Optional:}
\begin{itemize}
  \item Homebrew (\texttt{brew}), which also enables \texttt{brew -{}-cask}.
  \item \texttt{mas} (\texttt{brew install mas}) for Mac App Store
        upgrades.
\end{itemize}

\subsection{Windows}
\textbf{Required:} PowerShell 5.1 (built-in on Windows 10 and later) or 7+,
Git for Windows (needed by \texttt{up -{}-self-update}).

\textbf{Optional:}
\begin{itemize}
  \item \texttt{winget}, \texttt{scoop}, \texttt{choco}: any combination
        is auto-detected.
  \item \texttt{PSWindowsUpdate}
        (\texttt{Install-Module PSWindowsUpdate -Scope CurrentUser}) for
        Windows Update integration.
  \item \texttt{BurntToast}
        (\texttt{Install-Module BurntToast -Scope CurrentUser}) for
        native toast notifications.
\end{itemize}

\section{Installation}\label{sec:install}
%-------------------------------------------------------

\subsection{Linux and macOS}

\begin{lstlisting}[language=bashplus]
git clone https://github.com/MasterCruelty/eMerger
cd eMerger
./install.sh
# open a new shell, or: source ~/.bashrc
up --help
\end{lstlisting}

\texttt{install.sh}:

\begin{enumerate}
  \item Adds \verb|alias up='bash "/path/to/eMerger/src/emerger.sh"'| to
        your shell rc files (\texttt{.bashrc}, \texttt{.zshrc},
        \texttt{config.fish}). A checkout path containing a single or
        double quote, \verb|$|, a backquote, \verb|%|, a backslash or a
        newline is refused.
  \item Marks \texttt{src/emerger.sh} as executable.
  \item Installs shell completions for \texttt{bash}, \texttt{zsh} and
        \texttt{fish}:
        \begin{itemize}
          \item \verb|~/.local/share/bash-completion/completions/up|
          \item \verb|~/.zsh/completions/_up|
          \item \verb|~/.config/fish/completions/up.fish|
        \end{itemize}
  \item Installs the man page as \verb|~/.local/share/man/man1/up.1|, so
        \texttt{man up} shows it; if it does not, add
        \verb|~/.local/share/man| to \texttt{MANPATH}.
  \item Creates \verb|~/.config/emerger/| with \texttt{config.sh},
        \texttt{ignore.list}, \texttt{hooks/} and \texttt{profiles.d/}.
\end{enumerate}

On macOS the alias goes to \texttt{\string~/.zshrc} first, because
\texttt{zsh} is the default shell since Catalina. If Homebrew is present,
completions are installed under the Homebrew prefix.

\subsection{Windows}

\begin{lstlisting}[language=psplus]
git clone https://github.com/MasterCruelty/eMerger
cd eMerger
.\install.ps1
# open a new PowerShell window, or: . $PROFILE
up --help
\end{lstlisting}

\texttt{install.ps1} does not need administrator rights. It:

\begin{enumerate}
  \item When \texttt{ExecutionPolicy} for \texttt{CurrentUser} is
        \texttt{Restricted} or \texttt{Undefined}, asks before setting it
        to \texttt{RemoteSigned}; no answer (or no terminal) leaves it
        unchanged.
  \item Adds an \texttt{up} function that calls \texttt{emerger.ps1} to
        \verb|$PROFILE.CurrentUserAllHosts|, so \texttt{up} works in
        every PowerShell host (console, ISE, Windows Terminal, the
        VS Code terminal).
  \item Creates \verb|%APPDATA%\emerger\| with \texttt{config.ps1} and
        the \texttt{hooks} and \texttt{profiles.d} folders.
\end{enumerate}

When admin managers (choco, wsl, Windows Update) are detected, eMerger
runs them in one elevated child behind a single UAC prompt. The child
loads no \texttt{config.ps1}, profile or hook; its results, exit status
and log lines come back to the unelevated run, which prints them.

\subsection{Manual install}

Without the install script, point an alias or function at the entry
point:

\begin{lstlisting}[language=bashplus]
# bash, zsh, fish (Linux or macOS)
alias up='bash /absolute/path/to/eMerger/src/emerger.sh'
\end{lstlisting}

\begin{lstlisting}[language=psplus]
# PowerShell (Windows)
function up { & 'C:\path\to\eMerger\src\emerger.ps1' @args }
\end{lstlisting}

\subsection{Uninstall}

\begin{lstlisting}[language=bashplus]
./uninstall.sh     # Linux / macOS
.\uninstall.ps1    # Windows
\end{lstlisting}

Removes the alias or \texttt{up} function, the completion files, the man
page and any cron job, systemd user timer or scheduled task. It then asks
whether to delete the settings, history and cache too; the answer defaults
to no, and without a terminal they are kept. To remove them later by hand:

\begin{lstlisting}[language=bashplus]
rm -rf ~/.config/emerger ~/.local/state/emerger ~/.cache/emerger
\end{lstlisting}

The repo itself stays where it is; delete it by hand.

\section{Self-update}\label{sec:selfupdate}
%-------------------------------------------------------

\begin{lstlisting}[language=bashplus]
up -up                # short flag
up --self-update      # long flag
\end{lstlisting}

This runs \texttt{git pull -{}-ff-only} in the clone and prints the new
commit range. Non fast-forward updates are refused, so local changes are
never overwritten.

\section{Quickstart}\label{sec:quickstart}
%-------------------------------------------------------

Steps 1 and 3 change nothing on the system.

\subsection{Step 1: dry-run}
\begin{lstlisting}[language=bashplus]
up -n
\end{lstlisting}
Shows the detected managers and the commands that would run. It does
not ask for \texttt{sudo}, download anything or write to disk.

\subsection{Step 2: real run}
\begin{lstlisting}[language=bashplus]
up
\end{lstlisting}
Refreshes, upgrades and cleans each manager in turn. You get one
\texttt{sudo} prompt (Unix) or UAC prompt (Windows) if a manager needs it.

\subsection{Step 3: see what changed}
\begin{lstlisting}[language=bashplus]
up --changed
\end{lstlisting}
Prints the package diff for the last run with \texttt{+} for added,
\texttt{-} for removed and \texttt{\~} for upgraded.

\subsection{Step 4 (optional): weekly unattended update}
\begin{lstlisting}[language=bashplus]
up -au
\end{lstlisting}
Installs a systemd user timer (Linux), cron job (macOS) or scheduled task
(Windows): Sundays at 10:00 local time, with \texttt{-y -q -nl -ni}.
The timer and the task start up to one hour later at random; cron starts
at 10:00 sharp.

Output with apt and flatpak:

\begin{lstlisting}[basicstyle=\ttfamily\footnotesize]
$ up

  * apt  ~40s ------------------------------------------ #. 1/2
    [OK] fix broken ................   1.2s
    [OK] update ....................   6.8s
    .:. full-upgrade  .:::.   0:14  Unpacking libssl3 ...

  * flatpak -------------------------------------------- ## 2/2
    [OK] update ....................  12.4s  5 refreshed

  > User cache --------------------------------------------------
    ? Clean user cache? (812M) [y/N] y
    [OK] cache cleaned .............  812M

  +- eMerger summary ---------------------------+
  | managers  [OK] apt  [OK] flatpak            |
  | time      0m42s                             |
  | freed     812.0MB                           |
  | status    [OK] all good                     |
  +---------------------------------------------+
\end{lstlisting}

This is the ASCII glyph set (\texttt{-{}-ascii} or a non-UTF-8
locale). In a UTF-8 terminal you get rounded box corners, check marks, a
braille spinner and the \texttt{.:::.} wave; per-manager emoji icons need
a color-emoji font, otherwise plain symbols are used. A running step
shows the elapsed time and the last line the manager printed, then
collapses to one result line with duration and a short stat.

\begin{warn}
Don't run \texttt{sudo up}. eMerger asks for \texttt{sudo} itself, only
for the managers that need it. Under \verb|sudo up|, user-level packages
(\texttt{pip -{}-user}, Homebrew, \texttt{npm -g}) end up in root's home.
\end{warn}

\section{Execution flow}\label{sec:flow}
%-------------------------------------------------------
In order:

\begin{enumerate}
  \item Load \texttt{config.sh} (or \texttt{config.ps1}) if present.
  \item If \texttt{-{}-profile NAME} is on the command line, pre-load
        \verb|share/profiles/NAME.sh| (or the user override from
        \verb|~/.config/emerger/profiles.d/|).
  \item Parse CLI flags (they override config and profile).
  \item Unix: if \texttt{QUIET\_HOURS} is set, \texttt{-y} is set and the
        clock is inside the window, exit 0. Scheduled runs are skipped,
        interactive ones are not.
  \item Acquire the global exclusive lock (\verb|~/.local/state/emerger/emerger.lock| via
        \texttt{flock} on Unix, \verb|%LOCALAPPDATA%\emerger\state\run.lock| on Windows). If another \texttt{up} is already
        running, abort with exit code 1.
  \item Print the logo, OS info line and the current timestamp.
  \item Warn on low battery (<20\% on a laptop) and on low free disk
        space (default: less than 1024\,MiB on \texttt{/} or \texttt{C:}).
        On a Raspberry Pi, check power and temperature.
  \item Cache \texttt{sudo} credentials on Unix, only when a detected
        manager needs it. On Windows the admin managers run later in one
        elevated child.
  \item Unix: with \texttt{-{}-refresh-mirrors}, re-rank the mirrors; with
        \texttt{-{}-snapshot}, take a snapshot or exit 1.
  \item Snapshot the installed-packages list into \texttt{pkgs.before} for
        the post-run diff.
  \item Execute \texttt{pre.d} hooks in alphabetical order.
  \item For each detected manager, run \textit{refresh}, \textit{upgrade},
        \textit{clean}; serial for system managers, concurrent for safe
        user-space ones when \texttt{-{}-parallel} is active.
  \item Optionally clear user cache and trash (skippable with
        \texttt{-nc} and \texttt{-nt}), then, with
        \texttt{-{}-deep-clean}, the system leftovers and the container
        data (Unix).
  \item Execute \texttt{post.d} hooks.
  \item Snapshot the installed-packages list into \texttt{pkgs.after} and
        compute \texttt{pkgs.diff}.
  \item Render the boxed summary, the reboot advisory and an optional
        desktop notification.
  \item Exit 0 on success, 3 if any manager failed, 4 if a reboot is
        required and \texttt{-{}-reboot-exit} was passed.
\end{enumerate}

\subsection{Combining flags}
Any order, any combination. Single-letter short flags in the set \texttt{\{h V n v q y w\}} bundle
(\texttt{up -nv} equals \texttt{up -n -v}; \texttt{up -ynv} equals
\texttt{up -y -n -v}). Compound short flags (\texttt{-nl}, \texttt{-ni},
\texttt{-qq}, \texttt{-up}, \texttt{-err} and so on) and long flags are
never bundled.

\begin{lstlisting}[language=bashplus]
up -n -v                       # dry-run with live stream
up -y -q --security            # unattended security-only, minimal output
up --dev --parallel -v         # dev toolchains + user-space concurrency
up --snapshot -y && up --reboot   # snapshot, update, then reboot if needed
up --profile server --resume   # resume an interrupted headless run
up -n --dev --firmware         # preview a full run, no side effects
up -y -q -nl -ni               # what the scheduled timer runs
up --refresh-mirrors -y -v     # re-rank mirrors then upgrade, live
\end{lstlisting}

Flags that take a value (\texttt{-{}-profile NAME}, \texttt{-{}-changelog PKG},
\texttt{-{}-metrics FILE}, \texttt{-{}-only LIST},
\texttt{-{}-except LIST}) take it as the next word or as
\texttt{-{}-flag=VALUE} (\texttt{-{}-only=apt,flatpak}, \texttt{-{}-profile=work},
\texttt{-{}-changelog=bash}, \texttt{-{}-metrics=FILE}, \texttt{-{}-except=snap}).
An empty value exits 2. CLI flags
override config and profile, so you can tweak a profile for one run:

\begin{lstlisting}[language=bashplus]
up --profile work --dev        # work profile, but force --dev this time
\end{lstlisting}

\section{Features}\label{sec:features}
%-------------------------------------------------------

\subsection{Dry-run and verbose}
\texttt{-n} prints each command instead of running it, and does not ask
for elevation. Example output (apt and flatpak):

\begin{lstlisting}[basicstyle=\ttfamily\footnotesize]
$ up -n
    . [dry-run] sudo apt -o APT::Status-Fd=1 --fix-broken install -y
    . [dry-run] sudo apt -o APT::Status-Fd=1 update
    . [dry-run] sudo apt -o APT::Status-Fd=1 full-upgrade -y
    . [dry-run] sudo apt -o APT::Status-Fd=1 autoremove -y
    . [dry-run] sudo apt autoclean -y
    . [dry-run] sudo apt clean
    . [dry-run] flatpak update -y --noninteractive
    . [dry-run] flatpak uninstall --unused -y --noninteractive
\end{lstlisting}

\texttt{-v} streams each manager's output live instead of collapsing it
into one result line. Combine both with \texttt{up -n -v}.

\subsection{Quiet levels}
\begin{itemize}
  \item Default: logo, info line, section headers with step progress,
        spinner, per-step timings and the summary box.
  \item \texttt{-q}: hides muted and informational lines; keeps the
        per-manager result and the summary.
  \item \texttt{-qq}: only the one-line summary (good for systemd
        logs).
  \item \texttt{-qqq}: nothing, only the exit code.
\end{itemize}

\subsection{Security-only updates}
With \texttt{-{}-security}, managers that support it limit the upgrade to
security updates:

\begin{itemize}
  \item apt: \texttt{unattended-upgrade -v} when \texttt{unattended-upgrade}
        is installed; otherwise apt is skipped.
  \item dnf: \texttt{upgrade -{}-security}.
  \item yum: \texttt{update -{}-security}.
  \item zypper: \texttt{patch -{}-category security}.
  \item softwareupdate (macOS): \texttt{-{}-install -{}-recommended}
        (recommended updates, not only security ones), only with
        \texttt{-{}-accept-licenses}; without it the updates are listed.
\end{itemize}

On every platform every other manager is skipped with a warning, so
\texttt{-{}-security} never becomes a full upgrade; a plugin takes part
when it defines \verb|pm_<slug>_security|. On Windows,
Windows Update (PSWindowsUpdate) installs only the ``Security Updates''
category, and only with \texttt{-{}-accept-licenses}; without it the
updates are listed.

\subsection{Dev toolchains}
Off by default; \texttt{-{}-dev} turns on:

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
\textbf{Tool} & \textbf{Command} \\
\midrule
\texttt{rustup}  & \texttt{rustup update} \\
\texttt{cargo}   & \texttt{cargo install-update -a} \\
\texttt{npm}     & \texttt{npm update -g} \\
\texttt{pnpm}    & \texttt{pnpm -g update} \\
\texttt{pip}     & \texttt{pip list -{}-outdated}, then user-site upgrade \\
\texttt{gem}     & \texttt{gem update} \\
\bottomrule
\end{tabular}
\end{center}

Never run under \texttt{sudo}. Missing toolchains are skipped silently.

\subsection{Firmware (Linux)}
\texttt{-{}-firmware} runs
\texttt{fwupdmgr refresh \&\& fwupdmgr update -y -{}-no-reboot-check}.
On macOS firmware comes through \texttt{softwareupdate}; on Windows it is
left to vendor tools (Dell Command Update, Lenovo Vantage).
On a Raspberry Pi with an SPI EEPROM (Pi 4, 400, 5, 500, CM4, CM5)
\texttt{-{}-firmware} also stages the bootloader update with
\texttt{rpi-eeprom-update -a}; it is flashed on the next reboot.

\subsection{Raspberry Pi}\label{sec:rpi}
Detected from \verb|/proc/device-tree/model|.

\begin{itemize}
  \item Power and temperature: \texttt{vcgencmd get\_throttled}
        and \texttt{measure\_temp} are read before anything is installed
        and shown on one line. If the board is under-voltage \emph{right
        now}, eMerger warns that a brown-out while \texttt{dpkg} writes can
        corrupt the SD card and asks before continuing. With \texttt{-y} it
        warns and continues, unless \verb|RPI_ABORT_ON_UNDERVOLTAGE=1|.
        Past under-voltage since boot, and a SoC temperature above
        \verb|RPI_TEMP_WARN| (default 80\,$^\circ$C), are reported as warnings.
  \item Bootloader EEPROM (\texttt{rpi-eeprom} manager, boards with an
        SPI EEPROM only): every run checks for an update and reports it;
        \texttt{-{}-firmware} applies it and the reboot advisory says it
        will be flashed on next boot. \texttt{-{}-no-firmware} skips the check.
\end{itemize}

it arrives (on Windows, \texttt{pslib/ui/Monitor.ps1} and
\texttt{pslib/managers/Progress.ps1}):

\subsection{Cache cleaning}
The user-cache step lists the entries of \verb|~/.cache| biggest first,
with a size bar, and asks which to remove: \texttt{a} (all), \texttt{n}
(none, the default) or a list such as \texttt{1 3 5-7}. Entries past
\verb|CACHE_MENU_ROWS| (12) are grouped as one ``others'' row. eMerger's
own cache is always kept; \verb|CACHE_EXCLUDE="mozilla,pip*"| keeps more.
With \texttt{-y} everything not excluded is cleaned.

On Linux the step then reports the deleted files a running process
still keeps open on the filesystems of \texttt{/} and
\verb|$HOME|, when they hold 1M or more: the five biggest holders, by
command. That space comes back only when the holder closes the files or
exits, so nothing is deleted; restart the program named.

\subsection{Deep clean}\label{sec:deepclean}
\texttt{up -{}-deep-clean} goes after system-level leftovers a normal run
doesn't touch, asking about each one and showing how much it would free.
Skip tasks with \verb|DEEP_CLEAN_SKIP="docker,journal"|.

\begin{longtable}{@{}p{0.22\linewidth} p{0.70\linewidth}@{}}
\toprule
\textbf{Key} & \textbf{Task} \\
\midrule \endhead
\texttt{journal} & \verb|journalctl --vacuum-size=$JOURNAL_MAX_SIZE| (200M), only if bigger \\
\texttt{kernels} & dnf: keep the 2 newest kernels; zypper: \texttt{purge-kernels} \\
\texttt{residual} & \texttt{dpkg -{}-purge} config files of removed packages \\
\texttt{snap} & remove disabled snap revisions \\
\texttt{coredumps} & delete \verb|/var/lib/systemd/coredump| files \\
\texttt{npm}, \texttt{go} & \texttt{npm cache clean -{}-force}, \texttt{go clean -cache} \\
\bottomrule
\end{longtable}

Two more sections follow, with the same prompts and skip keys.

\begin{longtable}{@{}p{0.22\linewidth} p{0.70\linewidth}@{}}
\toprule
\textbf{Key} & \textbf{Task} \\
\midrule \endhead
\texttt{docker}, \texttt{podman} & Containers section, per local docker
      context (\texttt{unix://}; remote ones are skipped): \texttt{container prune -f}, \texttt{image prune -af},
      \texttt{builder prune -af} (docker only) and \texttt{volume prune}
      (\texttt{-af} on docker), each with its reclaimable size, a kind at
      0B not offered, sizes read again after the container prune. Stopped
      containers (toolbox, distrobox) and volumes hold data: never pruned
      under \texttt{-y}. Only the Linux system docker daemon is tried
      through \texttt{sudo}. Docker Desktop's data
      (\verb|~/.docker/desktop|, on macOS
      \verb|~/Library/Containers/com.docker.docker|) is shown from 1M,
      since its disk image shrinks only from Docker Desktop \\
\bottomrule
\end{longtable}

Respects \texttt{-n}; space freed on \texttt{/} goes into the summary.

\subsection{Parallel mode}
\texttt{-{}-parallel} runs user-space managers that do not touch the root
filesystem concurrently: \texttt{flatpak}, \texttt{snap}, \texttt{brew},
\texttt{mas}, and the dev toolchains. System managers (\texttt{apt},
\texttt{dnf}, \texttt{pacman}, \texttt{zypper} and so on) stay serial to
avoid lock contention on \texttt{/var/lib/dpkg}, \texttt{/var/cache/pacman}
and similar. Windows is always serial.

\subsection{Snapshots and rollback (Linux)}
\texttt{-{}-snapshot} tries, in order:

\begin{enumerate}
  \item \texttt{snapper}: a pre-update snapshot of the root subvolume,
        tagged \texttt{eMerger pre-update}.
  \item \texttt{timeshift}: \texttt{timeshift -{}-create -{}-tags D}.
  \item \texttt{btrfs subvolume snapshot}, only if neither of the above is
        installed. The snapshot goes under \verb|/.snapshots/emerger/|.
\end{enumerate}

If none of them works, eMerger names each failure and exits 1 before any
manager runs.

\texttt{-{}-rollback} goes back to the latest snapshot eMerger made:

\begin{itemize}
  \item snapper: \texttt{snapper -c root rollback <num>}, effective
        after a reboot.
  \item timeshift: runs \texttt{timeshift -{}-restore} interactively
        (\texttt{-{}-yes} is not passed).
  \item plain btrfs: eMerger does not swap subvolumes itself; it prints
        the path of the latest snapshot so you can do it by hand.
\end{itemize}

\subsection{Mirrors refresh (Linux)}
\texttt{-{}-refresh-mirrors} re-ranks mirrors before the upgrade:

\begin{itemize}
  \item Arch: \texttt{reflector -{}-latest 20 -{}-sort rate}.
  \item Debian (not its derivatives): \texttt{netselect-apt}, if installed, for the running release.
  \item Fedora: no-op, the \texttt{fastestmirror} plugin already does
        this.
\end{itemize}

\subsection{Reboot handling}
On Unix, eMerger inspects \texttt{/var/run/reboot-required} and
\texttt{needs-restarting -r} (if available). On Windows it reads these
registry entries:

\begin{itemize}
  \item \texttt{CBS\textbackslash RebootPending}
  \item \texttt{WindowsUpdate\textbackslash RebootRequired}
  \item \texttt{PendingFileRenameOperations}
\end{itemize}

\begin{itemize}
  \item The summary always prints a reboot advisory.
  \item \texttt{-{}-reboot} reboots the machine if needed (requires
        elevation).
  \item \texttt{-{}-reboot-exit} exits with code 4, so a calling script
        can decide what to do.
\end{itemize}

\subsection{Resume}
After each successful manager eMerger writes a cursor to
\verb|~/.local/state/emerger/resume|. \texttt{up -{}-resume} skips the
managers that finished in the last run. A run without
\texttt{-{}-resume} starts a fresh cursor, and a dry run leaves it alone.
Unix only.

\subsection{Package diff and changelog}
Every run records installed packages before and after. \texttt{up
-{}-changed} prints the diff (\texttt{+} added, \texttt{-} removed,
\texttt{\~} upgraded):

\begin{lstlisting}[basicstyle=\ttfamily\footnotesize]
$ up --changed
 ~ firefox          123.0.1   ->  124.0
 ~ libc6            2.39-0    ->  2.39-1
 + flatpak-xdg-utils 1.0.6
 - old-package      2.1
\end{lstlisting}

\texttt{up -{}-changelog PKG} shows one package's upstream changelog via
\texttt{apt changelog}, \texttt{dnf changelog} (or \texttt{updateinfo})
or \texttt{brew log}. pacman has no changelog: it shows the package info
(\texttt{pacman -Qi}) instead, labelled as such.

\subsection{History and errors}
\begin{itemize}
  \item \texttt{-{}-history} prints the last 10 runs as a table.
  \item \texttt{-err} / \texttt{-{}-errors} tails \texttt{ERROR} lines from
        \verb|~/.local/state/emerger/emerger.log|.
\end{itemize}

\subsection{Doctor}
\texttt{-{}-doctor} reports each of these as OK, warning or failure:

\begin{itemize}
  \item shell / PowerShell version;
  \item \texttt{sudo} cache / admin status;
  \item free space on \texttt{/} (\texttt{C:} on Windows) against
        \texttt{DISK\_MIN\_FREE\_MB};
  \item network reachability: one HTTPS request to \texttt{github.com}
        (Windows: one connection test to it);
  \item state directory writability;
  \item glyph mode (UTF-8, emoji font) and how to get emoji icons;
  \item per-manager native health: \texttt{dpkg -{}-audit},
        \texttt{pacman -Dk}, \texttt{dnf check} / \texttt{yum check},
        \texttt{brew doctor};
  \item pending reboot flag;
  \item (Windows) the current ExecutionPolicy and elevation status.
\end{itemize}

Exits non-zero if any check warns or fails. Please attach its output to
bug reports.

\section{Configuration}\label{sec:config}

\subsection{Config file (Unix)}

\verb|~/.config/emerger/config.sh| is a shell file sourced before
argument parsing. Each setting flag has a variable, listed under
``Every supported variable'' below:

\begin{lstlisting}[language=bashplus]
# ~/.config/emerger/config.sh

# Defaults
ARG_DEV=1                  # always include dev toolchains
ARG_WEATHER=1              # show weather widget via wttr.in
ARG_PARALLEL=1             # run user-space managers in parallel
ARG_KEEP_TRASH=1           # never empty the trash automatically

# Thresholds
DISK_MIN_FREE_MB=2048      # require at least 2 GiB free on /
BATTERY_MIN_PCT=25         # warn below 25%
RETRY_ATTEMPTS=3           # attempts on a transient network error
RETRY_DELAY=5              # first retry after 5s, second after 10s

# Scheduling
QUIET_HOURS="23:00-07:00"  # runs with -y exit 0 inside this window

# Caching
EMERGER_CACHE_TTL=3600     # detection cache: 1h (0 = disabled, default 86400)
\end{lstlisting}

\subsection{Config file (Windows)}

\verb|%APPDATA%\emerger\config.ps1| is dot-sourced before argument
parsing:

\begin{lstlisting}[language=psplus]
# %APPDATA%\emerger\config.ps1

$script:ArgsGlobal.Dev       = $true
$script:ArgsGlobal.Security  = $true
$script:ArgsGlobal.KeepTrash = $true
$script:UI_VERBOSE           = $true   # as -v

# Thresholds (same meaning as on Unix)
$script:DISK_MIN_FREE_MB = 4096
$script:RETRY_ATTEMPTS = 3
$script:MANAGER_TIMEOUT = 3600   # seconds per manager step, 0 = no limit
\end{lstlisting}

them (a file writable by your own private group is accepted). Running as
root with a \texttt{HOME} owned by another user, as \verb|sudo -E up| does,
is refused.

over \verb|ARG_FIRMWARE=1|.

\subsection{Profiles}\label{sec:profiles}
A profile is a config snippet loaded with \texttt{-{}-profile NAME}
(\texttt{up -{}-list-profiles} lists them). Shipped in
\texttt{share/profiles/}:

\begin{center}
\begin{tabular}{@{}p{0.16\linewidth} p{0.78\linewidth}@{}}
\toprule
\textbf{Profile} & \textbf{What it sets} \\
\midrule
\texttt{work}   & security only, unattended, cache and trash
                  left alone; Unix also: no firmware, skips yay and paru \\
\texttt{home}   & everything: dev toolchains; Unix also: firmware,
                  parallel mode and the weather line \\
\texttt{server} & headless: quiet (\texttt{-qq}), security only, no prompts,

Your own profiles go in \verb|profiles.d| under the config directory
(\verb|~/.config/emerger/| or \verb|%APPDATA%\emerger\|) and take
precedence over shipped ones with the same name. A \texttt{-{}-except} on the command line
adds to the profile's \texttt{ARG\_EXCEPT} instead of replacing it, and the
shipped profiles add to an \texttt{ARG\_EXCEPT} set in \verb|config.sh|.

The shipped \texttt{work} profile:

\begin{lstlisting}[language=bashplus]
# shellcheck shell=bash
# description: security only, unattended, no firmware, skips yay and paru
ARG_SECURITY=1
ARG_YES=1
ARG_NO_FIRMWARE=1
ARG_EXCEPT="${ARG_EXCEPT:+$ARG_EXCEPT,}yay,paru"
ARG_KEEP_CACHE=1
ARG_KEEP_TRASH=1
\end{lstlisting}

A custom one, used with \texttt{up -{}-profile train}:

\begin{lstlisting}[language=bashplus]
# ~/.config/emerger/profiles.d/train.sh
# description: prefetch only, quiet output
ARG_DOWNLOAD_ONLY=1
ARG_YES=1
QUIET_LEVEL=2
ARG_KEEP_TRASH=1
ARG_KEEP_CACHE=1
\end{lstlisting}

%-------------------------------------------------------
\section{Hooks}\label{sec:hooks}
%-------------------------------------------------------

Scripts in \texttt{hooks/pre.d/} (before updates) and
\texttt{hooks/post.d/} (after), run in alphabetical order. A failing hook
prints a warning and the run goes on. Unix hooks are \texttt{*.sh} files,
run with \texttt{bash} (no executable bit needed); Windows hooks are
\texttt{*.ps1} files, run in a child scope.

\subsection{Example: back up dotfiles before every run}

\begin{lstlisting}[language=bashplus]
# ~/.config/emerger/hooks/pre.d/10-backup-dotfiles.sh
#!/usr/bin/env bash
set -e
rsync -a --delete ~/.config/ ~/backups/dotfiles/
\end{lstlisting}

\subsection{Example: Slack notification after every run}

\begin{lstlisting}[language=bashplus]
# ~/.config/emerger/hooks/post.d/99-slack-notify.sh
#!/usr/bin/env bash
state=~/.local/state/emerger
tail -1 "$state/history.jsonl" | \
  curl -sS -X POST -H 'Content-Type: application/json' \
    --data-binary @- "$SLACK_WEBHOOK_URL" >/dev/null

\subsection{Example: copy the last run log to the clipboard (Windows)}

\begin{lstlisting}[language=psplus]
# %APPDATA%\emerger\hooks\post.d\10-log-to-clipboard.ps1
$log = Join-Path $env:LOCALAPPDATA 'emerger\state\emerger.log'
Get-Content $log -Tail 40 | Set-Clipboard
\end{lstlisting}

\begin{warn}
Hooks run with the privileges of whoever ran \texttt{up}, never as root.
When a detected manager needs \texttt{sudo}, eMerger caches the
credentials before the \texttt{pre.d} hooks, so a hook can call
\texttt{sudo -n}; in a run that needs no \texttt{sudo}, \texttt{sudo -n}
fails. A dedicated \texttt{sudoers} entry works in both cases. A dry run
lists the hooks and runs none.
\end{warn}

\textbf{Manager} & \textbf{Behavior} \\

\subsection{Quiet hours}
\texttt{QUIET\_HOURS="HH:MM-HH:MM"} in \texttt{config.sh}. A run that
starts inside the window with \texttt{-y} set (as timer runs are) exits
immediately; runs without \texttt{-y} are not affected. Windows across
midnight (\texttt{"23:00-07:00"}) work. A value in another format is
ignored with a warning.

\section{Manager plugins}\label{sec:plugins}
%-------------------------------------------------------

To add a package manager without touching the repo, drop a bash script
named \texttt{<slug>.sh} in \verb|~/.config/emerger/managers.d/|.

\subsection{Minimal plugin}

\begin{lstlisting}[language=bashplus]
# ~/.config/emerger/managers.d/mytool.sh
PM_PLUGIN_SLUG=mytool

pm_mytool_detect()     { command -v mytool >/dev/null 2>&1; }
pm_mytool_needs_sudo() { return 1; }     # optional, default: no sudo
pm_mytool_parallel()   { return 0; }     # optional, default: serial
pm_mytool_dev()        { return 1; }     # optional, default: not --dev gated
pm_mytool_icon()       { printf '\xf0\x9f\x94\x8c'; }   # optional
pm_mytool_security()   { return 1; }     # optional, 0: run honours ARG_SECURITY

pm_mytool_run() {
    run_cmd "mytool refresh"  mytool refresh  || return 1
    run_cmd "mytool upgrade"  mytool upgrade -y || return 1
    return 0
}
\end{lstlisting}

\subsection{Plugin API}
The file sets \verb|PM_PLUGIN_SLUG| and defines functions named after
it. A file without the slug, \verb|pm_<slug>_detect| or
\verb|pm_<slug>_run| is skipped with a warning.

\begin{center}
\begin{longtable}{@{}p{0.30\linewidth} p{0.12\linewidth} p{0.50\linewidth}@{}}
\toprule
\textbf{Name} & \textbf{Required} & \textbf{Contract} \\
\midrule \endhead
\verb|PM_PLUGIN_SLUG|       & yes & manager name, as shown and as matched by \texttt{-{}-only} \\
\verb|pm_<slug>_detect|     & yes & return 0 if the manager is installed \\
\verb|pm_<slug>_run|        & yes & refresh, upgrade, clean; return 0 on success \\
\verb|pm_<slug>_needs_sudo| & no  & return 0 if it needs root (default: no) \\
\verb|pm_<slug>_parallel|   & no  & return 0 if safe under \texttt{-{}-parallel} (default: serial) \\
\verb|pm_<slug>_dev|        & no  & return 0 to run only with \texttt{-{}-dev} \\
\verb|pm_<slug>_security|   & no  & return 0 if \verb|pm_<slug>_run| honours \verb|ARG_SECURITY|; without it \texttt{-{}-security} skips the plugin \\
\verb|pm_<slug>_icon|       & no  & print a short glyph \\
\verb|run_cmd LABEL CMD...| & helper & run one command with the features below \\
\bottomrule
\end{longtable}
\end{center}

\subsection{Behavior}
Plugins behave like built-in managers: \texttt{-{}-only},
\texttt{-{}-except}, \texttt{-{}-parallel}, \texttt{-{}-dev}, the detection
cache, hooks and the summary all apply to them. Commands run through
\texttt{run\_cmd} also get:

\begin{itemize}
  \item \texttt{-{}-dry-run} support;
  \item retry on transient failures (\texttt{RETRY\_ATTEMPTS}, \texttt{RETRY\_DELAY});
  \item logging to \verb|~/.local/state/emerger/emerger.log|;
  \item live-log streaming under \texttt{-v}.
\end{itemize}

Full template: \texttt{share/plugins/example.sh}.

\subsection{Detection cache}
Detection results are cached per manager slug in
\verb|~/.cache/emerger/detected| for 1 day. Set
\texttt{EMERGER\_CACHE\_TTL=<seconds>} in \texttt{config.sh} to change
this (0 disables the cache). Run \texttt{up -rc} after installing or
removing a package manager.

Windows loads no plugins.

\section{Integration}\label{sec:integration}
%-------------------------------------------------------

\subsection{JSON output}
\texttt{up -{}-json} prints one line of JSON on stdout, with no logo, info
line or summary box, so you can pipe it into \texttt{jq}:

\begin{lstlisting}[language=jsonplus]
{"ts":"2026-04-14T07:24:31Z","duration":42,"freed_kb":15360,
 "errors":0,"reboot":0,
 "managers":[{"name":"apt","result":"ok","secs":30},{"name":"flatpak","result":"ok","secs":12}]}
\end{lstlisting}

Hook output, plugin output and, with \texttt{-v}, manager output go to
stderr, so stdout holds the JSON line alone.

Every run except a dry run also appends this line to
\verb|~/.local/state/emerger/history.jsonl|
(\verb|%LOCALAPPDATA%\emerger\state\history.jsonl| on Windows). Both
platforms write the same fields.

\begin{center}
\begin{tabular}{@{}p{0.20\linewidth} p{0.72\linewidth}@{}}
\toprule
\textbf{Field}        & \textbf{Meaning} \\
\midrule
\texttt{ts}           & ISO 8601 UTC timestamp of the run end \\
\texttt{duration}     & total wall-clock seconds \\
\texttt{freed\_kb}    & cache and trash bytes freed, in KiB \\
\texttt{errors}       & number of managers that returned non-zero \\
\texttt{reboot}       & 1 if a reboot is required, else 0 \\
\texttt{managers}     & array of \texttt{\{name, result, secs\}} entries, \texttt{secs} being that manager's wall-clock seconds \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Prometheus metrics}
\texttt{up -{}-metrics FILE} writes the latest \texttt{history.jsonl}
entry in Prometheus textfile-collector format:

\begin{itemize}
  \item \texttt{emerger\_last\_run\_timestamp\_seconds}
  \item \texttt{emerger\_last\_run\_duration\_seconds}
  \item \texttt{emerger\_last\_run\_freed\_bytes}
  \item \texttt{emerger\_last\_run\_errors}
  \item \texttt{emerger\_reboot\_required}
  \item \texttt{emerger\_manager\_ok\{manager="..."\}} (one per manager)
\end{itemize}

It doesn't start a run; call it from a \texttt{post.d} hook or after
\texttt{up} in your timer. A field missing from the entry reads 0. On
Windows a last line that is not valid JSON exits 1.

\begin{lstlisting}[language=bashplus]
# ~/.config/emerger/hooks/post.d/90-prom.sh
up --metrics /var/lib/node_exporter/textfile_collector/emerger.prom
\end{lstlisting}

\subsection{Reboot exit code}
A successful run exits 0 even with a reboot pending (the summary says
\texttt{Reboot recommended}). With \texttt{-{}-reboot-exit} it exits 4
instead:

\begin{lstlisting}[language=bashplus]
up -y --reboot-exit
case $? in
    0) ;;                                   # done, no reboot needed
    3) notify-send "eMerger: some managers failed" ;;
    4) systemctl reboot ;;                  # clean, reboot required
esac
\end{lstlisting}

\subsection{Download-only}
\texttt{-{}-download-only} refreshes indexes
and downloads pending upgrades without installing them:

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
\textbf{Manager} & \textbf{Command} \\
\midrule
\texttt{pacman} & \texttt{pacman -Syuw} \\
\texttt{apt}    & \texttt{apt full-upgrade -y -{}-download-only}
                  (\texttt{dist-upgrade} with \texttt{apt-get}) \\
\texttt{dnf}    & \texttt{dnf upgrade -y -{}-downloadonly} \\
\texttt{zypper} & \texttt{zypper update -{}-download-only} \\
\texttt{softwareupdate} & \texttt{softwareupdate -{}-download -{}-all}
                  (\texttt{-{}-recommended} with \texttt{-{}-security}) \\
\bottomrule
\end{tabular}
\end{center}

The \texttt{apt} repair step (\texttt{-{}-fix-broken install}) also runs
with \texttt{-{}-download-only}. Every other manager, plugins included,
is skipped with a message, so nothing installs.

\subsection{Manager filtering}
\begin{lstlisting}[language=bashplus]
up --only apt,flatpak        # only these managers
up --except snap,fwupd       # everything else
\end{lstlisting}

Filters apply after detection and after \texttt{-{}-dev} /
\texttt{-{}-firmware} gating, so:

\begin{itemize}
  \item \texttt{-{}-only X} runs nothing if \texttt{X} is not detected.
  \item \texttt{-{}-except} beats \texttt{-{}-only} when both name the
        same manager.
  \item \texttt{-{}-except} adds to a list from \texttt{config.sh} or a
        profile instead of replacing it (\texttt{up -{}-profile safe
        -{}-except npm} skips flatpak, snap and npm).
\end{itemize}

\section{Auto-update (unattended)}\label{sec:auto}
%-------------------------------------------------------

\begin{lstlisting}[language=bashplus]
up -au             # Linux / macOS
\end{lstlisting}
\begin{lstlisting}[language=psplus]
up -au             # Windows
\end{lstlisting}

\begin{itemize}
  \item Linux: a systemd user timer at
        \verb|~/.config/systemd/user/emerger.{service,timer}|, or cron
        when \texttt{systemctl -{}-user} is not available.
  \item macOS: cron, via \texttt{crontab -l} (set up \texttt{launchd}
        yourself if you prefer it).
  \item Windows: \texttt{Register-ScheduledTask -TaskName eMerger}. When
        an admin manager (choco, wsl, Windows Update) is present, the run
        raises a UAC prompt at the scheduled time and keeps the run lock
        until it is answered.
\end{itemize}

Weekly, Sunday 10:00 local time (up to one hour later at random, except
under cron), always with
\texttt{-y -q -nl -ni}. On Linux and macOS, use \texttt{QUIET\_HOURS} to
keep runs out of a time window. On Linux, systemd user timers don't fire without an open
login session; run \texttt{loginctl enable-linger \$USER} once (as root)
to fix that.

\begin{lstlisting}[language=bashplus]

systemctl --user status emerger.timer
systemctl --user stop emerger.timer
systemctl --user disable emerger.timer
\end{lstlisting}

\begin{lstlisting}[language=psplus]
# Windows
Get-ScheduledTask eMerger
Unregister-ScheduledTask eMerger
\end{lstlisting}

\section{Security model}\label{sec:security}
%-------------------------------------------------------

\begin{itemize}
  \item Runs when you call it, or from the timer installed with
        \texttt{-au}. No open ports. During a run it keeps two helper
        processes, both gone when the run ends: the progress monitor and,
        when a manager needs \texttt{sudo}, a refresher that renews the
        \texttt{sudo} ticket every 60 seconds.
  \item Its own state lives in \verb|~/.config/emerger/|,
        \verb|~/.cache/emerger/| and \verb|~/.local/state/emerger/|
        (the lock file \texttt{emerger.lock} included). State and cache
        directories are private (mode 0700).
  \item It also writes, only when asked: the \texttt{up} alias and
        completion files (\texttt{install.sh}), a systemd user timer or
        crontab line (\texttt{-au}), the mirror list
        (\texttt{-{}-refresh-mirrors}), a snapshot (\texttt{-{}-snapshot}),
        the \texttt{-{}-metrics} file, and deletions inside
        \verb|~/.cache| and the Trash when cleaning.
        \texttt{-{}-deep-clean} also deletes journal entries, old kernels,
        leftover configs, snap revisions, crash dumps
        (\verb|/var/lib/systemd/coredump|), unused containers, images,
        build cache and volumes, after asking for each.
  \item On Windows, UAC elevation happens only for the managers that need
        admin. They run in an elevated child that loads no config, profile
        or hook. That child runs the code of the checkout: clone it into a
        folder only administrators can write to if other programs running
        as you must not reach admin rights. The child starts with
        \texttt{PATH} and \texttt{PSModulePath} reduced to system folders, so
        a tool or module in a folder you can write is not run elevated.
        \texttt{ComSpec} and \texttt{PATHEXT} are reset, \texttt{ChocolateyInstall}
        comes from the machine scope, and the \texttt{DOTNET\_*}, \texttt{COR\_*},
        \texttt{CORECLR\_*}, \texttt{COMPlus\_*} and
        \texttt{PSExecutionPolicyPreference} variables are removed before
        the managers run. Variables that act when a process starts (a
        profiler or startup hook set in your user environment) have already
        acted on the elevated PowerShell by then: keep your user environment
        free of them. A
        \texttt{choco} or \texttt{wsl} outside Windows, System32, Program
        Files, or a \texttt{ProgramData\textbackslash chocolatey} that
        standard users can write, is refused.
        \texttt{choco upgrade all -y} accepts package licences and runs only
        with \texttt{-{}-accept-licenses}; without it \texttt{choco outdated}
        lists the upgrades. Every child PowerShell (elevated child, step
        runner, scheduled task) starts with \texttt{-ExecutionPolicy Bypass},
        so the \texttt{RemoteSigned} policy does not apply to \texttt{up}'s
        own scripts.
  \item Linux and macOS: config files, profiles, plugins and hooks are
        refused when another user could change them. The file and its
        directory must belong to you and not be writable by group or
        others (your own private group excepted).
  \item The checkout runs as you, and as root under \texttt{sudo}. Keep it
        writable by you alone: \texttt{up} refuses to start when a file
        under \verb|src/| is writable by group or others (your private
        group excepted).
  \item Hooks and plugins run as you and can do anything you can. Only
        install ones you trust.
  \item With \texttt{-v} the managers write to the terminal directly;
        otherwise their output is stripped of terminal control sequences.
  \item eMerger's own network traffic: the optional weather line
        (\texttt{wttr.in}), \texttt{git pull} for \texttt{-{}-self-update},
        \texttt{fwupdmgr refresh} with \texttt{-{}-firmware}, and one
        connectivity check to \texttt{github.com} during
        \texttt{-{}-doctor}, and with \texttt{-{}-refresh-mirrors} the mirror
        lists that \texttt{reflector} and \texttt{netselect-apt} fetch.
        Everything else comes from the package managers.
  \item No telemetry. \texttt{history.jsonl} stays local
        unless one of your hooks sends it somewhere.
\end{itemize}

\section{Troubleshooting}\label{sec:trouble}
%-------------------------------------------------------

\paragraph{``Another eMerger run is in progress''.}
Another \texttt{up} holds the lock, and the message names its PID. Wait
for it, or stop that process (\texttt{kill PID}). Deleting the lock file
does not release a \texttt{flock}: it lets a second run start beside the
first. A process started by a hook or a manager never holds the lock.
On Windows the message names the lock file, not a PID: wait for the
other \texttt{up} window (or the scheduled task) to finish. An elevated
window left running by an interrupted \texttt{up} also holds off the next
run of the same account until it ends; the elevated child creates its lock
in the state directory of the account it runs under and does not start
without it.

\paragraph{A manager fails with exit code 3.}
\texttt{up -{}-errors}, then \texttt{up -{}-doctor}. Usually it's the
manager's own state (e.g.\ an interrupted \texttt{dpkg}); run its repair
command (\texttt{sudo dpkg -{}-configure -a}, \texttt{sudo pacman -Dk})
and retry.

\paragraph{Nothing happens on scheduled runs.}
Check \texttt{systemctl -{}-user status emerger.timer} or Task Scheduler,
and the \texttt{enable-linger} note in section \ref{sec:auto}. To see the
output of a scheduled run, add \texttt{-v} in the unit once.

\paragraph{Emoji renders as boxes or question marks.}
Emoji icons are used only when fontconfig reports a color-emoji font.
Install one (\texttt{sudo apt install fonts-noto-color-emoji} on
Debian/Raspberry Pi OS), force the mode with \verb|EMERGER_EMOJI=1| or
\verb|EMERGER_EMOJI=0|, or use \texttt{-{}-ascii}.
\texttt{up -{}-doctor} shows the active mode.

\paragraph{The run seems stuck at ``User cache'' or ``Trash''.}
It's waiting at a y/N prompt (read from \verb|/dev/tty|, defaults to
``no'' after \verb|EMERGER_PROMPT_TIMEOUT| seconds). \texttt{-y} skips it.

\paragraph{``cannot read the Trash (macOS privacy settings)''.}
macOS hides \verb|~/.Trash| from a terminal without Full Disk Access.
Grant it to your terminal in System Settings, Privacy \& Security, Full
Disk Access.

\paragraph{Warnings appear even with \texttt{-{}-json}.}
They go to stderr, so stdout is only the JSON. Add \verb|2>/dev/null|.

\paragraph{\texttt{up -{}-self-update} aborts with ``non fast-forward''.}
You have local commits on top of \texttt{main}. Rebase or reset yourself.

\paragraph{\texttt{notify-send} (Linux) never shows a notification.}
No \texttt{DISPLAY} / \texttt{WAYLAND\_DISPLAY} (usual under cron). Use
the systemd user timer, which inherits the session.

\paragraph{(Windows) ``up : The term `up' is not recognized''.}
The profile wasn't loaded. Run \texttt{. \$PROFILE} or open a new
window; if that fails, run \texttt{.\textbackslash install.ps1} again.

\paragraph{(Windows) ``cannot be loaded because running scripts is disabled''.}
\texttt{ExecutionPolicy} is \texttt{Restricted}. Run:

\begin{lstlisting}[language=psplus]
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
\end{lstlisting}

\paragraph{(Windows) choco, wsl or Windows Update fail with ``elevation failed''.}
The UAC prompt was cancelled. Those managers count as failed (exit 3),
the rest of the run goes on. Run \texttt{up} again and accept the prompt.

\paragraph{Pacman warns about ignored packages.}
That's pacman's own message for \texttt{-{}-ignore=}.

\section{Frequently asked questions}\label{sec:faq}
%-------------------------------------------------------

\paragraph{Can I use it on production servers?}
Yes: \verb|up --profile server| (unattended, security-only). Add
\texttt{-{}-reboot-exit} and let your own tooling decide when to reboot.

\paragraph{Does \texttt{up} install packages I don't have?}
No. It only upgrades what's installed, with managers that are installed.
New packages show up only as new dependencies of an upgrade.

\paragraph{Does \texttt{up} reboot my machine?}
Only with \texttt{-{}-reboot}.

\paragraph{Can I use it without \texttt{sudo}?}
Yes, limit it to user-level managers:

\begin{lstlisting}[language=bashplus]
up --only flatpak,brew,npm,pip,cargo
\end{lstlisting}

\paragraph{Why does the terminal flicker with \texttt{-{}-parallel -v}?}
Every user-space manager streams output at once. Drop \texttt{-v}, or
narrow the set with \texttt{-{}-only}.

\paragraph{Can I use it in a Docker image build?}
Yes: \verb|up --only apt -y -qq| (or your manager). Skip
\texttt{-{}-firmware} and \texttt{-{}-snapshot}, and ignore the reboot
advisory.

\subsection{Running tests}

With bats-core and ShellCheck on \texttt{PATH}:

\begin{lstlisting}[language=bashplus]
bats tests/
shopt -s globstar
shellcheck -S error src/emerger.sh src/lib/**/*.sh install.sh uninstall.sh
\end{lstlisting}

Each \texttt{tests/<feature>.bats} covers one feature: \texttt{cli.bats}
the flags, \texttt{lock.bats} the run lock, \texttt{clean.bats} the cache,
trash and \texttt{-{}-deep-clean}, and so on.
\texttt{tests/test\_helper.bash} holds the shared fixture (temp
\texttt{HOME}, stubs on \texttt{PATH}, \texttt{lib} to source modules). The
\texttt{tests/ps\_*.bats} files cover the PowerShell half and skip without
\texttt{pwsh}. All of them run on push via
\texttt{.github/workflows/ci.yml}.

\subsection{Adding a package manager}

\paragraph{Unix:} edit \texttt{src/lib/managers/}.

\begin{enumerate}
  \item Add the name to \texttt{PKG\_MANAGERS} (\texttt{registry.sh}).
  \item Add a branch in \texttt{\_pkg\_detect\_raw} (\texttt{detect.sh}).
  \item Add a \texttt{\_pkg\_run\_<name>} recipe with \texttt{run\_cmd}
        calls and its case in \texttt{pkg\_run} (\texttt{recipes.sh}).
  \item If the manager does not need sudo, exclude it from
        \texttt{pkg\_needs\_sudo} (\texttt{registry.sh}).
  \item Optional: an emoji (and plain-symbol fallback) in
        \texttt{pkg\_icon} (\texttt{icon.sh}), a stat parser in
        \texttt{progress\_summarize}, a live-progress case in
        \texttt{progress\_feed} (\texttt{progress.sh}) and a completion entry.
\end{enumerate}

\paragraph{Windows:} edit \texttt{src/pslib/managers/Packages.ps1}.

\begin{enumerate}
  \item Add the name to \texttt{\$script:PKG\_MANAGERS} (or
        \texttt{PKG\_DEV}).
  \item Add a \texttt{Pkg-Detect} case.
  \item Add a \texttt{Pkg-Run} case with \texttt{Run-Cmd} calls.
  \item If it needs admin, add it to \texttt{Pkg-Need-Admin}.
\end{enumerate}

Both dispatchers are table-driven, so a new manager is usually a short
patch plus a test under \texttt{tests/}.

\subsection{Contributing}
Issues and pull requests go to
\href{https://github.com/MasterCruelty/eMerger}{GitHub}, against
\texttt{dev}. Before opening a PR:

\begin{itemize}
  \item Run the test suite in \texttt{tests/} on the platform you
        touched.
  \item Attach \texttt{up -{}-doctor} output and the relevant chunk of the
        log when reporting bugs.
  \item If a feature applies to both Bash and PowerShell, implement it on
        both or say in the PR that the other side is missing.
\end{itemize}
